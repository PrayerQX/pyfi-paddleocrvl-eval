# 专业领域文档评测方法论

## 目标

把 PyFi 的“金融图像 + 问题 + 选项 + 能力层级 + 复杂度”抽象成通用评测流程，迁移到医疗、法律、工业票据等专业文档场景。

## 标准流程

1. 定义任务边界  
   明确是 OCR、版面解析、表格解析、图表理解、VQA，还是“解析 + 下游问答”的复合任务。

2. 建立领域能力阶梯  
   PyFi 的 6 层可以迁移成模板：
   `感知/基础识别 -> 显式信息抽取 -> 计算分析 -> 模式识别 -> 逻辑推理 -> 专业决策支持`。

3. 设计最小可复现实验集  
   从全量数据中抽取固定 seed 的公开 split。建议先做 300 条左右的 smoke/evidence split，再扩展到 1k、10k 和全量。

4. 标注结构化 gold  
   对选择题，gold 是选项字母；对解析任务，gold 应包含文本、表格、bbox、阅读顺序、结构标签和图表数据。

5. 保留中间产物  
   文档解析模型必须保存 Markdown/JSON/HTML/表格文件；复合链路不能只保存最终答案。

6. 分层报告指标  
   至少报告 overall、领域能力层级、复杂度、文档类型、语言、图像质量、失败类型。

7. 做统计和人工审计  
   对关键结论做 bootstrap 置信区间；对胜负边界样本做人工复核。

8. 写 claim gate  
   先定义什么结果足以支持“首选模型”。例如：准确率不低于竞品、解析失败率更低、成本或延迟更优。

## 迁移到医疗领域

医疗文档可以把能力层级改成：

- Perception：识别表格、曲线、影像标注、检查单字段。
- Data_extraction：抽取检验值、单位、参考区间、日期。
- Calculation_analysis：计算变化率、异常次数、评分量表。
- Pattern_recognition：识别趋势、异常组合、时序变化。
- Logical_reasoning：结合多字段推断检查结论是否一致。
- Decision_support：辅助分诊、随访建议、质控提醒。

医疗场景必须额外加入：

- 隐私脱敏和数据授权。
- 医疗安全等级标注。
- 人工复核与双人仲裁。
- 禁止把模型输出当作诊断结论。

## 工具边界

本仓库当前适合做：

- 多选 VQA 指标评测。
- 文档解析结果作为下游问答证据的评测。
- 分层指标报告。
- 可复现样本 split 和 artifact 保存。

还需要补充的部分：

- 专门的表格结构指标，例如 TEDS、单元格匹配。
- OCR 字符级/词级指标，例如 CER/WER。
- 图表数据重建指标。
- 统计显著性脚本。
